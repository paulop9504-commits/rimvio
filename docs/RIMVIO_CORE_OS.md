# Rimvio Core OS — Agent Loop · State · Runtime Protocol

**Status:** CANON (engineering SSOT for Core vs Dev boundary)  
**ADR:** [062-rimvio-core-vs-dev-runtime.md](./adr/062-rimvio-core-vs-dev-runtime.md)  
**Wire:** `lib/rimvio-core/` · `lib/workstream/` · `lib/context-run/` · `lib/hub/dev/*-registry.ts`

> Rimvio의 OS 레이어는 **수많은 Capability가 아니라** Protocol + Runtime + State + Agent Loop다.  
> Dev는 SDK로 Capability · Runtime · Adapter · Infrastructure를 Hub에 올린다.

## 2. Rimvio Core (우리가 만든다)

```text
┌────────────────────────────────────────┐
│              RIMVIO CORE               │
│  Agent Loop                            │
│    → Planner / Reasoner                │
│    → Capability Resolver               │
│    → Runtime Router                    │
│    → Permission / Policy               │
│    → State Manager (Task SSOT)         │
│    → Checkpoint / Recovery             │
│    → Event / Execution Log             │
│    → Tool Registry (scoped per task)   │
│    → Capability Registry + Compatibility│
└────────────────────┬───────────────────┘
                     │
               Runtime Protocol
```

| Component | Role | Current wire (Rimvio repo) |
|-----------|------|----------------------------|
| Agent Loop | Observe→Plan→Execute→Verify→Repair | `lib/context-run/workspace-agent-loop.ts` · `rimvio-agent-spine.ts` |
| Planner | Task graph · capability scope | `planObjectDiscovery` · `compile-workspace-agent-plan.ts` |
| State | Task / execution SSOT | `lib/workstream/agent-execution-session.ts` · `task-state.ts` types |
| Policy | Prepare→Commit · guards | `lib/agent-policy/` · ADR-049 |
| Tool Registry | Scoped tools per turn | `lib/tool-registry/` · `@` registry |
| Capability Registry | Agent discovery | `lib/platform-sdk/capability-index.ts` |
| Capability Specification | 6-pillar contract (not code) | `lib/rimvio-protocol/capability-specification.ts` · ADR-063 |
| Runtime Router | Pick runtime for action | `lib/rimvio-core/runtime-router.ts` · Hub Registry |
| Checkpoint | Resume after interrupt | Roadmap · `task-state.checkpoints` |

**LLM in the loop:** single-shot이 아니라 `Observation → state.update → replan`.

## 3. Task State (SSOT)

Chat ≠ Task. UI는 Task State를 구독한다.

```typescript
// lib/rimvio-core/task-state.ts — canonical shape
Task {
  id, user_id, goal, status, current_step
  context, plan
  completed_steps, pending_steps
  active_capabilities, active_runtime
  execution_history, errors, approvals, checkpoints
  created_at, updated_at
}
```

Example UI:

```text
로그인 기능 구현 중…
✓ 프로젝트 분석
✓ Auth 코드 생성
→ 테스트 중…
○ Build · Deploy
```

Persistence target: Supabase + realtime subscription (roadmap).

## 4. Dev layer (SDK + Hub)

### Rimvio Runtime Protocol

Dev implements; Rimvio Core calls via Router.

| API | Purpose |
|-----|---------|
| `execute(action)` | Run tool/capability step |
| `observe()` | Read environment |
| `pause()` / `resume()` / `cancel()` | Human-in-the-loop |

| Surface | Examples |
|---------|----------|
| filesystem · terminal · browser · git | PC / Cloud Core |
| network · process · context · permission | All tiers |

### Execution stack (mandatory)

```text
Capability
    ↓
Rimvio Interface (tools + permissions)
    ↓
Runtime Router (Core)
    ↓
Runtime (Core or Dev-published)
    ↓
Infrastructure (Dev-published, via Adapter)
```

### Dev SDK (target)

```typescript
rimvio.capability({
  name, input, tools, permissions,
  execute: async (ctx) => { ... }
})
rimvio.runtime({ ... })  // implements Runtime Protocol
```

Manifest · Permission · Runtime interface generated by SDK.

### Hub — four stores

| Store | What Dev publishes |
|-------|-------------------|
| **Capability Store** | Business logic blocks |
| **Runtime Store** | PC / Browser / Industrial / Cloud / Mobile runtimes |
| **Infrastructure Store** | PLC · cloud region · supplier API · device fleet |
| **Adapter Store** | Runtime ↔ Infrastructure bridge |

**Core Runtime** (`tier: "core"`) — Rimvio ships PC · Browser · Cloud.  
**Extension Runtime** (`tier: "extension"`) — Dev registers (Factory · Robot · Android…).

Security: **Rimvio Core Standard** — Permission Model · Context · Capability Protocol · Runtime API · Security Policy · Verification. Dev cannot opt out.

## 6. What Rimvio is *not* building for Dev

- Custom Agent Loop per platform  
- Chat-as-SSOT task tracking  
- Capability bypassing Runtime Protocol  
- Rimvio as merchant-of-record for all payments (ADR-060)
